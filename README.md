# beautyBOT — Telegram-бот для бьюти-мастеров (клон функционала BeautyAgent)

Clean-room реализация по методологии REA. Платформа: Telegram Cloud serverless (@tgcloud).

## Структура

| Путь | Что это |
|---|---|
| `reports/` | REA-доказательства (шаги 1–2): поведение оригинала, платформа |
| `spec.md` | Behavior-only спецификация — **единственный вход для билдера** (шаг 3) |
| `docs/manual-tests.md` | Ручные чек-листы приёмки по фазам |
| `bot/tgcloud/` | Код бота: `schema.js`, `lib/` (логика), `handlers/` (update-типы) |
| `bot/scripts/` | Локальные тесты чистых модулей (`node scripts/test-time.mjs`) |
| `comparison.md` | (шаг 5 REA) оригинал vs клон — появится в Фазе 6 |

## Фазы

0. ✅ Каркас: схема БД, доступ по белому списку, онбординг мастера, меню, движок слотов (13 групп локальных тестов)
1. Ядро календаря: услуги, рабочие часы, время-оф, шаблоны, записи
2. CRM клиентов
3. Онлайн-запись клиентом через бота
4. Напоминания (/tick + внешний cron), рассылки
5. Финансы и статистика
6. Итерация (сравнение с оригиналом, полировка)

## Работа с ботом

```bash
cd bot
npx tgcloud login     # один раз: CLI-токен из @BotFather (бот → Serverless)
npx tgcloud push      # деплой кода
npx tgcloud migrate   # применить изменения схемы БД
npx tgcloud run handlers/message '{"message":{...}}'  # проверка модуля без деплоя
node scripts/test-time.mjs  # локальные тесты слотов/таймзон
```

Напоминания: внешний cron каждые 5 минут шлёт боту `/tick` в чат администратора
(настраивается в Фазе 4; на платформе нет планировщика — см. reports/03).
