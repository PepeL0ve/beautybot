# Решение: платформа — Telegram Cloud serverless

**Дата**: 2026-11-03
**Статус**: Принято

## Контекст

Нужна платформа для мультиарендного Telegram-бота с хранением состояния
(записи, клиенты, настройки). Должна масштабироваться под нагрузку и
не требовать отдельного сервера.

## Рассматриваемые варианты

1. **Cloudflare Workers + D1** — надёжно, но отдельный деплой и конфиг.
2. **Telegram Cloud serverless (@tgcloud)** — код рядом с Telegram, webhook
   управляется платформой, БД встроена.
3. **VPS + long polling** — полный контроль, но обслуживание сервера.

## Решение

Выбран **@tgcloud**: меньше инфраструктуры, естественная интеграция с
Bot API, встроенная SQLite, деплой одной командой.

## Последствия

- Нет планировщика → внешний cron → `/tick` (см. [[003-reminders-cron]])
- Нет npm-пакетов в рантайме → только Intl для таймзон
- Нет внешних ключей → целостность в коде, каскадные удаления вручную
- Только `handlers/` и `endpoints/` запускаемы; `lib/` — только импорт

## Альтернатива (fallback)

Если @tgcloud недоступен: Cloudflare Workers + D1, та же архитектура
хендлеров, но свой webhook и конфиг БД.
