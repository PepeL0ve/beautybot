# Решение: напоминания через внешний cron + /tick

**Дата**: 2026-11-03
**Статус**: Принято

## Контекст

На платформе @tgcloud нет планировщика: код выполняется только при входящем
update (сообщение, нажатие кнопки). Но напоминания о записях должны уходить
клиентам вовремя, даже если никто ничего не пишет.

## Рассматриваемые варианты

1. **Ленивая проверка** — напоминание уходит при следующем обращении клиента
   или мастера к боту. Может опоздать на часы/дни.
2. **Внешний cron → /tick** — внешний бесплатный cron (cron-job.org,
   GitHub Actions) каждые 5 минут шлёт боту скрытую команду `/tick` в чат
   администратора через Bot API. Хендлер перехватывает её и выполняет sweep
   просроченных напоминаний для всех мастеров.
3. **Отдельный сервис-сторож** — отдельный воркер на другой платформе
   (усложняет архитектуру).

## Решение

Выбран **вариант 2**: внешний cron + `/tick`.

## Последствия

- Нужна настройка cron-job.org (5 минут, бесплатно) — делается в Фазе 4
- Плюс ленивая проверка при каждом update мастера как страховка
- Напоминания клиентам приходят вовремя (±5 минут), а не только при обращении
- Все задачи собираются в `lib/svc/sweep.js`: ap_before, pending_stale,
  lost_client, birthday, waitlist_offer, продолжение рассылок
