# SPEC — Telegram-бот «МастерЗапись» (behavior-only, clean-room)

Версия: 1.0 (2026-11-03). Вход для билдера: этот файл + reports/03 (платформа).
Запрещено: копировать код/имена/тексты/ассеты каких-либо существующих продуктов.

## 0. Продукт

Telegram-бот для мастеров бьюти-сферы: расписание, онлайн-запись клиентов,
база клиентов, напоминания, рассылки, учёт денег. Мультиарендный: один бот —
много изолированных мастеров. Доступ мастера — только по предварительному
внесению в белый список.

Роли:
- **Мастер** — владелец своего кабинета (услуги, расписание, клиенты, деньги).
- **Клиент** — любой пользователь Telegram, пришедший по ссылке мастера.

## 1. Платформа и структура проекта

Telegram Cloud serverless (@tgcloud): JS ESM, без npm в рантайме, только SDK.
Хендлеры — по файлу на тип update: `handlers/message.js`,
`handlers/callback_query.js`, `handlers/my_chat_member.js`. Общий код в `lib/`
(вложенности разрешены только там). БД `sdk.db` — SQLite, ДСЛ в стиле Drizzle,
**без внешних ключей** — целостность в коде.

```
bot/
├── lib/
│   ├── schema.js      # все таблицы
│   ├── time.js        # чистые функции дат/слотов (Intl, без библиотек)
│   ├── access.js      # белый список + tenant-резолвер
│   ├── state.js       # FSM-диалоги (таблица bot_states)
│   ├── fmt.js         # форматирование денег/дат/длительностей
│   ├── i18n/ru.js     # ВСЕ тексты интерфейса — только здесь
│   ├── kb.js          # билдеры инлайн-клавиатур
│   └── svc/           # бизнес-логика: schedule, slots, booking, clients,
│                      # reminders, sweep, mailings, finance, stats
├── handlers/
│   ├── message.js         # команды, FSM-ввод текстом, перехват /tick
│   ├── callback_query.js  # единый роутер callback_data
│   └── my_chat_member.js  # блокировка бота клиентом
└── endpoints/             # пусто (резерв Mini App, Фаза 6)
```

Callback_data схема (парсится единым роутером): `<область>:<действие>:<id>` —
например `ap:cancel:123`, `bk:day:2026-11-05`, `fin:rep:month`.

## 2. Данные (schema.js)

Все id — `integer().primaryKey({ autoIncrement: true })`. Денег — integer
копеек. Даты — ISO-строки `YYYY-MM-DD`, время — минуты от 00:00 (int).
Без FK; связи по явным полям `master_id`/`client_id`/etc., удаляем каскадно
в сервисном коде.

- `access_list` — tg_user_id (unique), note, added_at
- `masters` — id, tg_user_id (unique), tg_chat_id, name, public_blurb,
  public_photo_file_id, master_code (уникальная строка-слаг для ссылок,
  8 символов A-Z2-9), timezone (строка IANA, дефолт `Europe/Moscow`),
  settings json (п.14), created_at
- `services` — id, master_id, name, duration_min, price_cents, price_from
  (bool «цена от»), description, is_popular (bool, вручную), sort, active
- `work_hours` — id, master_id, weekday (0=Пн..6=Вс), start_min, end_min,
  enabled. Уникальность (master_id, weekday) в коде.
- `time_off` — id, master_id, date, start_min (nullable = весь день),
  end_min, kind (`break`|`dayoff`|`personal`), note
- `schedule_templates` — id, master_id, name, payload json: массив
  {weekday, start_min, end_min, enabled}
- `clients` — id, master_id, tg_user_id (nullable, если добавлен вручную),
  tg_chat_id, display_name, phone, username, birthday (`MM-DD`), notes,
  blacklisted (bool), archived (bool), unreachable (bool), created_at.
  Уникальность (master_id, tg_user_id) при не-null tg_user_id.
- `appointments` — id, master_id, client_id, service_id (nullable для
  свободного сеанса без услуги), starts_at (ISO datetime), ends_at,
  status (`pending`|`confirmed`|`completed`|`canceled`|`no_show`),
  price_cents, prepaid (bool), note, source (`self`|`master`), created_by,
  canceled_at
- `waiting_list` — id, master_id, client_id, service_id, date_from, date_to,
  status (`active`|`notified`|`booked`|`expired`), created_at
- `reviews` — id, master_id, appointment_id, client_id, rating (1–5), text
- `client_groups` — id, master_id, name
- `client_group_members` — group_id, client_id
- `mailings` — id, master_id, text, target_kind (`all`|`group`|`category`),
  target_ref, status (`draft`|`sending`|`done`), sent, failed, cursor
- `finance_entries` — id, master_id, kind (`income`|`expense`), amount_cents,
  category, entry_date, note, appointment_id (nullable)
- `reminders` — id, master_id, appointment_id (nullable), client_id,
  kind (`ap_before`|`lost_client`|`birthday`|`waitlist_offer`),
  send_at (ISO), sent_at (nullable), payload json
- `bot_states` — chat_id (pk), user_id, state (строка), data json, updated_at
- `ticks` — id, ran_at, note (журнал sweep)

## 3. Доступ и мультиарендность

- `/start` без payload: если tg_user_id есть в `access_list` и мастера нет →
  онбординг; если мастер есть → главное меню.
- Если нет в `access_list` → сообщение «доступ выдаёт администратор, ваш
  ID: <id>» и ничего больше. Клиент без payload: приглашение получить ссылку
  у своего мастера.
- `/start book_<master_code>`: резолв мастера по коду → клиентский режим
  (п.10). Клиенту регистрация не нужна.
- Изоляция: КАЖДЫЙ запрос данных фильтруется по master_id из сессии.
  Клиент видит только записи, где он client_id.

## 4. Онбординг мастера

FSM-диалог: 1) имя (отображаемое, по умолчанию из Telegram) → 2) часовой
пояс (по умолчанию Europe/Moscow, выбор из популярных) → 3) приглашение
добавить 1–3 услуги (name + длительность + цена, можно пропустить) →
4) главная ссылка записи `t.me/<bot>?start=book_<master_code>`.
Повторный онбординг запрещён (мастер уже есть).

## 5. Каталог услуг (мастер)

Меню «Услуги»: список с ценой/длительностью. Действия: добавить (FSM:
название → длительность (кнопки 30/45/60/90/120 + свой ввод минут) → цена →
«цена от?» → описание (опц.) → популярная?); редактировать поля по одному;
вкл/выкл (active); удалить (если нет будущих записей — иначе запрет).
Сортировка ручная (вверх/вниз). Дефолт новых услуг: не популярная, active.

## 6. Расписание (мастер)

- Рабочие часы по дням недели: включить/выключить день, время начала/конца
  (FSM ввод `HH:MM`), несколько интервалов не требуется (один на день).
- Время-оф на конкретную дату: перерыв (с–по), выходной (весь день),
  личное дело (с–по, note). Просмотр списка на 14 дней вперёд, удаление.
- Шаблоны: сохранить текущие work_hours как шаблон; применить шаблон на
  диапазон дат (переписывает work_hours); предустановленный шаблон
  «Пн–Пт 10:00–19:00».
- Просмотр «Свободные окна на дату» — результат движка слотов (п.7).

## 7. Движок слотов (lib/time.js + svc/slots) — чистые функции

Вход: master_id, дата, длительность услуги. Шаг сетки: 15 мин.
Свободный слот = [t, t+duration) такой, что:
1) попадает в work_hours этого дня (weekday=дата), день enabled;
2) не пересекается ни с одним time_off этой даты;
3) не пересекается ни с одной appointments в статусе
   pending/confirmed/completed в этот день;
4) «липкие окна» (settings.sticky_min, дефолт 0): до/после каждой записи
   добавляется буфер sticky_min, слот не может его пересекать;
5) t >= сейчас + settings.min_lead_min (дефолт 60) — нельзя записаться в
   прошлое и слишком срочно.
Выход: отсортированный список начал слотов. День без рабочих часов = пусто.
Грани: слот ровно впритык к записи разрешён (пересечение строгое);
слот, выходящий за конец рабочего дня, запрещён.

## 8. Записи (мастер)

- Вид «Сегодня»: список записей дня по времени (клиент, услуга, статус,
  цена, флажок предоплаты) + счётчик свободных окон. Вид «Неделя»:
  7 строк — дата, количество записей, число свободных окон.
- Создать вручную (FSM): клиент (из базы или новый: имя [+телефон]) →
  услуга → дата → время из слотов ИЛИ произвольное `HH:MM` (пересечение
  запрещено, предупреждение) → подтверждение. source=master,
  статус=confirmed.
- Карточка записи: перенести (дата → слоты), отменить, завершить, неявка,
  предоплата вкл/выкл, изменить цену (для «цены от»), заметка, удалить.
  Отмена: причина не запрашивается; клиенту (если активен в боте) уходит
  уведомление + предложение встать в лист ожидания на это же окно.
- Завершить: статус completed + автозапись дохода (если
  settings.auto_income, п.14) + клиенту просьба оценить ⭐ (п.12).

## 9. Клиенты (мастер, CRM)

- Список: поиск по подстроке имени/телефона; фильтры: все / новые /
  постоянные / «потеряшки» / в архиве / в чёрном списке / группа;
  пагинация по 8.
- Категории (пересчитываются запросом, пороги в settings):
  новый — визитов < settings.regular_visits (дефолт 3); постоянный — ≥;
  «потеряшка» — прошёл settings.lost_days (дефолт 30) с последнего
  завершённого визита и визитов ≥ 1.
- Карточка: контакты, д/р, username, категория, визиты (n), история
  (последние 10 записей), группы, заметки; действия: записать, редактировать
  (FSM по полям), добавить/убрать из групп, в чёрный список / вернуть,
  в архив / вернуть, удалить (вместе с будущими записями — запрет, если
  есть pending/confirmed).
- Клиент создаётся автоматически при первой записи через бота (из Telegram
  профиля) или вручную мастером (без tg_user_id — недостижим ботом,
  напоминания — текстом для копирования).

## 10. Онлайн-запись (клиент, тот же бот)

- Вход по `book_<master_code>`: визитка — фото (если есть), имя мастера,
  blurb, популярные услуги, кнопки [Записаться] [Мои записи] [Оставить
  отзыв]. Кнопки действий только после первого визита.
- Флоу [Записаться]: услуга (список active, цена «от», длительность) →
  дата (следующие settings.book_days_ahead=14 дней с числом свободных
  окон, пустые дни скрыты) → слот (п.7) → подтверждение
  (услуга/дата-время/цена) → запись создана.
- Если settings.auto_confirm → сразу confirmed + уведомление мастеру.
  Иначе pending → мастеру карточка [✅ Принять] [❌ Отклонить]
  (+ таймаут-напоминание через /tick, если не обработана 2ч —
  settings.pending_remind_min=120).
- Если settings.only_existing и клиента нет в базе мастера → вежливый отказ
  («запись для постоянных клиентов — свяжитесь с мастером»).
- Чёрный список: клиенту не показываются слоты, отказ без деталей.
- [Мои записи]: будущие записи у ЭТОГО мастера: статус, дата, услуга;
  отмена клиентом → запись canceled → мастер получает уведомление; слот
  освобождается; предложение: «сообщить, если это окно освободится» →
  waiting_list.
- Отмена/неявка не портят историю: canceled/no_show остаются в истории,
  в категориях не учитываются.

## 11. Лист ожидания

Мастер: список желающих (клиент, услуга, диапазон дат), удалить/выполнено.
Клиент: одна активная заявка на мастера. Когда /tick находит новую
свободную вилку (после отмены записи) на дату из диапазона — уведомление
клиенту с кнопкой «Записаться» (статус notified, повторно не спамим —
одна заявка = одно уведомление до действия клиента).

## 12. Отзывы

После завершения записи клиенту инлайн ⭐1–5 (+ опциональный текст FSM).
Отзыв сохраняется; мастер видит средний рейтинг и последние отзывы в
«Настройки → Страница записи». Повторный отзыв на ту же запись невозможен.

## 13. Напоминания и /tick (svc/sweep)

`/tick` (скрытая команда, доступна только чату из settings.admin_chat_id,
реакция — пустая) и ленивый sweep при каждом update мастера (не чаще раза
в 5 мин) выполняют всё просроченное:

1. `ap_before`: за N минут до записи (settings.remind_offsets_min,
   дефолт [1440, 120]) клиенту текст с датой/временем/услугой/мастером.
   Один reminder на (appointment_id, offset) — не дублируются.
2. Pending-заявка без ответа > pending_remind_min → напоминание мастеру.
3. «Потеряшки»: раз в сутки дайджест мастеру — список клиентов, у которых
   сегодня lost_days с последнего визита (с готовым текстом для отправки).
4. Дни рождения: за 1 день и в день — клиенту поздравление (если
   settings.birthday_greet), мастеру в дайджест.
5. Лист ожидания: предложение освободившихся окон (п.11).
6. Недостижимость: ошибка 403 → clients.unreachable=true, напоминания
   этому клиенту прекращаются, в рассылке считается failed.

Reminders планируются при создании записи (ap_before) и при изменении
времени (перепланируются). Отменённая запись → её reminders удаляются.

## 14. Настройки мастера (settings json, дефолты)

auto_confirm=false; only_existing=false; sticky_min=0; min_lead_min=60;
book_days_ahead=14; remind_offsets_min=[1440,120]; pending_remind_min=120;
regular_visits=3; lost_days=30; auto_income=true; birthday_greet=true;
admin_chat_id=chat_id мастера при онбординге.
Меню «Настройки»: тумблеры по каждому булеву/числу, редактирование
страницы записи (имя, blurb, фото — FSM/фото-сообщение), регенерация
master_code, просмотр ссылок и QR-ссылки (текстом; QR-картинка — Фаза 6).

## 15. Рассылки

Мастер: аудитория (все / группа / категория) → текст (FSM) → предпросмотр
→ подтверждение → mailings.status=sending. Отправка чанками по
MAILING_CHUNK (константа 20) за инвокацию, продолжение на следующем /tick
(processing: беру mailings с cursor < sent+failed, шлю следующую партию
активным (не blacklisted/unreachable) клиентам мастера, имеющим tg_chat_id;
403 → unreachable++/failed++, прочие ошибки → failed++). Итог: «отправлено
N, недоставлено M (из них X не запускали бота — текст для ручной отправки
в карточке)». Готовый текст с подстановкой {имя} доступен в карточке
каждого клиента.

## 16. Финансы

- Доход: авто из завершённых записей (auto_income, категория «Услуги»,
  appointment_id проставлен) и вручную (FSM: сумма → категория из списка →
  дата → заметка). Расход: аналогично.
- Отчёты за период (сегодня/неделя/месяц/произвольный): доход, расход,
  прибыль, топ услуг по выручке, число визитов, новые клиенты.
- Прогноз месяца: средний доход/день × оставшиеся дни (INFERRED-модель,
  подписана в UI как оценка).
- Удаление записи-дохода (завершённой) удаляет связанный finance_entry.

## 17. Общие правила UX/ошибок

Все сообщения из i18n/ru.js. Кнопки «⬅️ Назад» и «🏠 Меню» в каждом диалоге;
«❌ Отмена» обрывает FSM без побочных эффектов. FSM-ввод с таймаутом без
лимита (состояние в БД персистентно). Ошибки БД/SDK ловятся, пользователю —
общий текст «Что-то пошло не так, попробуйте ещё раз», детали — console.
Всё время мастеру показывается в его timezone; клиенту — в мастере
timezone слота (клиент знает пояс мастера из визитки).

## 18. Тест-кейсы (приёмочные)

T1 Доступ: /start не из access_list → отказ с ID; после внесения → онбординг.
T2 Онбординг повторно → меню, а не повторная регистрация.
T3 Услуги: добавить/редактировать/скрыть/удалить; удалить услугу с будущими
   записями → запрет.
T4 Расписание: Пн 10–19; слот 10:00–12:00 при услуге 60 мин → слоты 10:00…
   18:00 (последний 18:00); при sticky_min=15 → 10:00…17:45 c записью в 10:00
   → первый валидный слот 12:15.
T5 Пересечение: запись 11:00–12:00; попытка создать вручную 11:30 → отказ.
T6 Время-оф весь день → в этот день слотов нет.
T7 Запись клиентом: полный флоу; pending → мастер видит ✅/❌; принять →
   статус confirmed у клиента.
T8 auto_confirm=true → сразу confirmed.
T9 only_existing=true → новый клиент не может записаться.
T10 Чёрный список → слоты недоступны.
T11 Отмена клиентом → мастер уведомлён; другой клиент в листе ожидания
    на этот день → получает предложение; повторного спама нет.
T12 Отзыв: ⭐ и текст сохраняются; повтор на ту же запись невозможен.
T13 /tick: запись через 25 мин, офсет 120 → после /tick мастеру+клиенту
    уходит по одному напоминанию; повторный /tick — дубликата нет.
T14 403: клиент заблокировал бота → unreachable=true, рассылка идёт дальше.
T15 Рассылка 45 клиентам, чанк 20: за один /tick уходит ≤20, курсор движется,
    после трёх /tick статус done, счётчики корректны.
T16 Финансы: завершение записи → income создан (auto_income); отчёт за месяц
    сходится; удаление записи удаляет income.
T17 Мультиарендность: два мастера — услуги/клиенты/записи друг друга не видят.
T18 Часовой пояс: мастер UTC+5, слот 10:00 локально — в БД правильный UTC.
T19 FSM: «Отмена» на любом шаге не создаёт мусора в БД.
T20 Клиент без активаций бота (добавлен вручную) в напоминаниях даёт
    готовый текст, а не попытку отправки.
