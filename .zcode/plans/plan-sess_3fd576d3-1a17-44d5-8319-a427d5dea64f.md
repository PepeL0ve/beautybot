# Telegram-бот-клон BeautyAgent — план по методологии REA (clean-room)

## Context
Цель — Telegram-бот с функционалом https://app.beautyagent.ru/: платформа для бьюти-мастеров (календарь, онлайн-запись, CRM клиентов, напоминания, рассылки, финансы). Реверс-инжиниринг по процессу REA: поведение описываем **только по публичным источникам** (лендинг, App Store, доки Telegram), evidence — в `reports/`, затем собираем behavior-only `spec.md`, и билдер строит строго по spec.md без доступа к оригиналу (никаких копий кода/имён/ассетов — clean-room).

Согласованные решения:
- Клиенты записываются **через этого же бота** (deep link → inline-кнопки)
- **Мультиарендная платформа**, мастера регистрируются только по белому списку ID (`access_list`)
- Стек: **Telegram Cloud serverless (@tgcloud)** — JS ESM без npm в рантайме, `sdk/db` (SQLite, **без FK** — целостность в коде), хендлеры = 1 файл на тип update
- Разработка **по фазам**, ядро сначала
- Напоминания: **внешний cron + /tick** (плюс ленивая проверка при каждом update)

## Архитектура

```
beautyBOT/
├── reports/                 # шаг 2 REA: evidence (лендинг, App Store, платформа)
├── spec.md                  # шаг 3 REA: behavior-only спецификация (вход для билдера)
├── comparison.md            # шаг 5 REA: оригинал vs клон
├── docs/manual-tests.md     # чек-листы по фазам
└── bot/                     # проект @tgcloud (npm create @tgcloud/bot)
    ├── package.json         # только CLI-зависимости
    ├── lib/
    │   ├── schema.js        # таблицы sdk/db
    │   ├── time.js          # слоты/даты на Intl (без библиотек!)
    │   ├── access.js        # белый список
    │   ├── state.js         # FSM диалогов (таблица bot_states)
    │   ├── i18n/ru.js       # все тексты интерфейса
    │   ├── keyboards.js     # инлайн-клавиатуры
    │   └── svc/             # schedule, booking, clients, mailings, finance, notify, sweep
    ├── handlers/
    │   ├── message.js       # команды, FSM-ввод, перехват /tick
    │   ├── callback_query.js# все кнопки
    │   └── my_chat_member.js# блокировка бота → подавление напоминаний
    └── endpoints/           # резерв под Mini App (опционально, Фаза 6)
```

**Данные** (sdk/db, FK нет): `access_list`, `masters` (settings json: авто-подтверждение, офсеты напоминаний, пороги категорий, «липкие окна»), `services`, `work_hours`, `time_off`, `schedule_templates`, `clients`, `appointments` (pending/confirmed/completed/canceled/no_show, предоплата), `waiting_list`, `reviews`, `client_groups`, `mailings`, `finance_entries`, `reminders`, `bot_states`, `ticks`.

**Движок слотов**: свободные окна = рабочие часы − время-оф − занятые записи − «липкий» буфер; чистые функции в `lib/time.js`/`svc/schedule`.

**Клиентский сценарий** (тот же бот): `/start book_<master_code>` → визитка мастера (фото, описание, популярные услуги) → услуга → день (14 дней) → слот → заявка мастеру ✅/❌ → статус клиенту; «Мои записи»; отмена → предложение листа ожидания; отзыв ⭐1–5.

**Мастер-сценарий**: `/start` → проверка `access_list` → онбординг (имя, услуги) → меню: 📅 Записи · 🗓 Расписание · 👥 Клиенты · 📣 Рассылка · 💰 Финансы · ⚙️ Настройки · 🔗 Моя ссылка.

**Ограничения Bot API** (учесть в spec): бот пишет клиенту только если тот запускал бота — остальным мастер копирует готовый текст (как в оригинале); рассылки ≤30 msg/с, чанками; 403 при отправке → пометка «недостижим».

## Фазы (каждая = работающий бот, проверка с вами между фазами)

- **Фаза 0 — REA-документы + каркас**: `reports/` (3 файла), `spec.md`, `docs/manual-tests.md`; настройка BotFather → Serverless → CLI-токен (нужно ваше действие), `tgcloud init`, hello-world, `schema.js`, `access_list`, онбординг мастера, скелет меню. Проверить UNKNOWN: Intl TZ, лимиты инвокаций.
- **Фаза 1 — Ядро календаря**: каталог услуг CRUD, рабочие часы, время-оф, шаблоны на недели/месяцы, движок слотов, записи вручную (создать/перенести/отменить/завершить/неявка/предоплата), виды день/неделя.
- **Фаза 2 — CRM**: список/поиск/карточка, история посещений, авто-категории, группы, чёрный список, архив, ручное добавление.
- **Фаза 3 — Онлайн-запись**: deep links, клиентский флоу записи, подтверждение/отклонение, авто-подтверждение, «только свои», лист ожидания, «Мои записи», отзывы.
- **Фаза 4 — Ассистент**: cron-job.org (5 мин) → `/tick`, sweep: напоминания о записях (по умолч. за 24ч/2ч), дайджест «потеряшек», предложения из листа ожидания, дни рождения; рассылки чанками с отчётом.
- **Фаза 5 — Финансы/статистика**: доходы (авто из завершённых) /расходы, отчёты за период, чистая прибыль, прогноз, статистика посещений.
- **Фаза 6 — Итерация (шаг 5 REA)**: `comparison.md` — 3 сильных стороны оригинала сохранить, 3 слабости, улучшения; полировка; опционально QR и Mini App-страница записи.

**Fallback**: если Serverless недоступен в BotFather — Cloudflare Workers + D1, архитектура хендлеров портируется 1:1.

## Верификация
- Каждая фаза: `npx tgcloud run <module> '<json5>'` для сервисов + живой тест по чек-листу `docs/manual-tests.md` (сценарий мастера + клиента со второго Telegram-аккаунта)
- Мультиарендность: 2 мастера → изолированные данные
- Напоминания: запись через 25 мин → ручной `/tick` → уведомление пришло
- Отказоустойчивость: клиент заблокировал бота → 403 → пометка, рассылка не падает
- Финал: сверка со spec.md → `comparison.md`

Первый шаг после одобрения — Фаза 0: вам нужно будет включить Serverless у бота в @BotFather и выдать мне CLI-токен.
